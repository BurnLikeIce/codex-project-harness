# Codex 项目协作 Harness

这是一套可复用的项目协作模板，用来让多个 Codex 对话在同一个软件项目里协同工作。

## 它能做什么

- 把项目里的第一个对话变成主控/集成对话。
- 创建共享项目文档和不同角色的初始提示词。
- 提供功能对话交付给产品验收的任务交付模板。
- 提供短口令形式的需求分发和问题分流规则。
- 支持把自然语言请求映射到对应流程，不要求记住精确口令。
- 支持用很短的自然语言提示启动新项目或接管旧项目。
- 提供产品验收和返工指令模板。
- 协调产品、前端、后端、Bug/CI、实验对话。
- 标准化 Git/GitHub 分支、PR、合并流程。

## 在项目里使用

在新项目或已有项目的第一个对话里说：

```text
请使用 project-harness skill 启动这个项目。
从现在开始，本对话就是项目主控/集成对话。
```

如果是已有项目，可以说：

```text
请使用 project-harness skill，把当前已有项目迁移到多对话协作框架里。
不要覆盖已有文档，先检查并给出迁移计划。
```

## 推荐协作流程

1. 主控对话安装或检查 harness。
2. 旧项目里可以让主控对话“用 project-harness 接管旧项目，并先给迁移计划”。
3. 在产品对话里用 `新需求：...` 或类似自然表达开始需求澄清。
4. 用 `需求讨论结束，请分发任务。` 让产品对话创建任务指令。
5. 用 `问题：...` 或类似自然表达发给你觉得最相关的对话；收到问题的对话会处理或升级。
6. 前端/后端对话按任务 ID 开发，并输出任务交付。
7. 产品对话对交付结果给出通过、不通过或有条件通过。
8. 主控对话 review、验证、合并已通过产品验收的工作。

## 核心原则

聊天负责讨论和执行，文档负责同步。不要在多个对话之间复制大段聊天记录，而是把共识写进 `docs/`，再用任务 ID 分发。
