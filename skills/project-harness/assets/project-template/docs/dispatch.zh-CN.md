# 需求分发规则

产品/架构对话处理新需求时使用这个文档。精确短口令和类似自然表达都可以触发；用户说得比较随意时，按 `docs/intent.zh-CN.md` 判断意图。

## 短口令

开始需求澄清：

```text
新需求：<描述>
```

结束讨论并分发任务：

```text
需求讨论结束，请分发任务。
```

类似自然表达也有效，例如“好，就这么做”“按这个方案开始吧”“安排一下”“拆一下任务”。

## 产品对话行为

需求澄清阶段：

- 简短提问，澄清目标、范围、边界和验收标准。
- 不让前端/后端直接开工。
- 判断会影响哪些对话：前端、后端、Bugfix、实验、主控。

任务分发阶段：

- 更新相关文档。
- 在 `docs/tasks.md` 创建或更新任务 ID。
- 标注任务依赖关系。
- 输出可直接复制给目标对话的指令。

## 分发输出格式

```md
## 需求分发：<需求名>

已更新文档：
- [ ] `docs/product.md`
- [ ] `docs/architecture.md`
- [ ] `docs/api-contract.md`
- [ ] `docs/tasks.md`
- [ ] `docs/decisions.md`

任务拆分：
- <任务ID>：<任务名> -> <负责对话>

依赖关系：
- <任务ID> 依赖 <任务ID>

可直接复制给 <负责对话> 的指令：

```text
请按照 prompts/<role>.zh-CN.md 工作，处理 <任务ID>。
任务要求以 docs/tasks.md 中的 <任务ID> 为准。
完成后请按 docs/completion.zh-CN.md 输出任务交付，交给产品对话验收。
不要合并到 main。
```
```
