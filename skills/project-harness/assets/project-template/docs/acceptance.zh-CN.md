# 验收与返工模板

产品/架构对话验收其他对话的交付结果时使用这个文档。通常做法是：用户把前端、后端、Bugfix 或实验对话的结果总结、截图、PR 摘要、测试结果等直接复制给产品对话，然后产品对话按下面格式输出验收结论和下一步指令。

## 验收规则

每次验收必须给出下面三种结论之一：

- `通过`
- `不通过`
- `有条件通过`

如果不是完全通过，必须明确指出哪里不通过，并给出可以直接复制给对应对话的返工指令。不要只说“没做好”“不符合预期”。

## 输出格式

```md
## 任务验收：FE-001 / BE-001 / BUG-001

结论：通过 / 不通过 / 有条件通过

未通过点：
- 具体指出哪里不符合需求、验收标准或产品预期。
- 如果有多个问题，逐条列出。

需要返工的对话：
- 前端 / 后端 / 主控 / 产品 / Bugfix / 实验

需要更新的文档：
- [ ] `docs/tasks.md`
- [ ] `docs/product.md`
- [ ] `docs/api-contract.md`
- [ ] `docs/architecture.md`
- [ ] `docs/decisions.md`

可直接复制给对应对话的指令：

```text
请继续处理 FE-001。

产品验收未通过，原因：
- ...
- ...

请完成以下返工：
- ...
- ...

要求：
- 继续使用当前分支/工作树。
- 如涉及 API 或产品行为变化，请更新对应 docs。
- 完成后运行相关验证，并把结果交回主控/产品对话复验。
```

主控对话下一步：
- 在返工完成前不要合并相关 PR。
- 将任务状态更新为 `In Progress` 或 `Rework`。
```

## 通过示例

```text
FE-001 验收通过。

通过原因：
- 页面行为符合 docs/tasks.md 中的验收标准。
- 空状态、加载状态和错误状态都已覆盖。
- 截图与产品预期一致。

主控对话下一步：
- 可以进入 PR review 和合并前验证。
- 合并后将 FE-001 标记为 Done。
```

## 不通过示例

```text
FE-001 验收不通过。

未通过点：
- 移动端布局不符合验收标准，卡片在 390px 宽度下出现横向溢出。
- 缺少空状态，用户没有数据时页面显示为空白。
- Dashboard 卡片字段和 docs/product.md 里的产品定义不一致。

需要返工的对话：
- 前端

需要更新的文档：
- [ ] docs/tasks.md

可直接复制给前端对话的指令：

请继续处理 FE-001。

产品验收未通过，原因：
- 移动端布局在 390px 宽度下横向溢出。
- 缺少空状态。
- Dashboard 卡片字段与 docs/product.md 不一致。

请完成以下返工：
- 修复移动端布局，确保 390px 宽度下无横向滚动。
- 增加空状态展示。
- 按 docs/product.md 调整卡片字段。
- 完成后运行 lint/build，并交回主控和产品对话复验。

主控对话下一步：
- 在返工完成前不要合并 FE-001 对应 PR。
- 将 FE-001 状态标记为 Rework。
```

## 有条件通过示例

```text
BE-001 有条件通过。

条件：
- 合并前需要补充错误响应场景测试。

需要返工的对话：
- 后端

可直接复制给后端对话的指令：

请继续处理 BE-001。

产品验收为有条件通过，合并前必须补充：
- 为错误响应场景增加测试。
- 确认响应结构仍符合 docs/api-contract.md。

完成后把测试结果交回主控对话。若响应结构变化，请同步更新 docs/api-contract.md。
```
