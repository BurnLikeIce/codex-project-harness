# 验收与返工模板

产品/架构对话验收其他对话的交付结果时使用这个文档。通常做法是：用户把前端、后端、Bugfix 或实验对话的结果总结、PR 摘要、测试结果等直接复制给产品对话，然后产品对话输出验收结论和下一步指令。

## 验收规则

每次验收必须给出下面三种结论之一：

- `通过`
- `不通过`
- `有条件通过`

每次验收都必须输出“下一步交接”：

- 通过：给出可直接复制给主控对话的下一步指令。
- 不通过：指出未通过点，并给出可直接复制给返工对话的指令，同时告诉主控不要合并。
- 有条件通过：说明条件，给出可直接复制给返工对话的补充指令，同时告诉主控满足条件前不要合并。

不要只输出“验收通过”或“验收不通过”。

## 输出格式

```md
## 任务验收：<任务ID>

结论：通过 / 不通过 / 有条件通过

验收判断：
- <为什么通过、不通过或有条件通过>

未通过点 / 条件：
- <如果通过，写“无”>
- <如果不通过或有条件通过，逐条列出>

需要返工的对话：
- <通过时写“无”>
- <不通过或有条件通过时写：前端 / 后端 / Bugfix / 实验 / 其他>

需要更新的文档：
- [ ] `docs/tasks.md`
- [ ] `docs/product.md`
- [ ] `docs/api-contract.md`
- [ ] `docs/architecture.md`
- [ ] `docs/decisions.md`

可直接复制给返工对话的指令：

```text
<通过时写：无>
<不通过或有条件通过时，写给负责返工对话的具体指令>
```

可直接复制给主控对话的指令：

```text
<无论通过、不通过、有条件通过，都必须填写>
```
```

## 通过示例

```text
FE-001 验收通过。

验收判断：
- 页面行为符合 docs/tasks.md 中的验收标准。
- 空状态、加载状态和错误状态都已覆盖。
- 交付结果符合产品预期。

未通过点 / 条件：
- 无

需要返工的对话：
- 无

需要更新的文档：
- [ ] docs/tasks.md
- [ ] docs/changelog.md

可直接复制给返工对话的指令：

无

可直接复制给主控对话的指令：

请继续处理 FE-001 的主控 review 和合并前验证。

产品验收已通过。

请主控对话执行：
- 检查 FE-001 对应分支/PR 的 diff。
- 运行相关测试、lint、build。
- 确认 docs/tasks.md 状态可更新。
- 如果验证通过，按项目 PR 流程合并。
- 合并后将 FE-001 标记为 Done，并更新 docs/changelog.md。
```

## 不通过示例

```text
FE-001 验收不通过。

验收判断：
- 当前交付结果没有满足移动端和空状态验收标准。

未通过点 / 条件：
- 移动端布局在 390px 宽度下横向溢出。
- 缺少空状态。
- Dashboard 卡片字段与 docs/product.md 不一致。

需要返工的对话：
- 前端

需要更新的文档：
- [ ] docs/tasks.md

可直接复制给前端对话的指令：

请继续处理 FE-001。

产品验收未通过，原因：
- 移动端布局在 390px 宽度下横向溢出。
- 缺少空状态。
- Dashboard 卡片字段与 docs/product.md 不一致。

请完成以下返工：
- 修复移动端布局，确保 390px 宽度下无横向滚动。
- 增加空状态展示。
- 按 docs/product.md 调整卡片字段。
- 完成后运行相关验证，并按 docs/completion.zh-CN.md 重新交付给产品验收。

可直接复制给主控对话的指令：

FE-001 产品验收未通过，请暂缓 review/合并。

请主控对话执行：
- 不要合并 FE-001 对应 PR。
- 将 docs/tasks.md 中 FE-001 状态标记为 Rework 或 In Progress。
- 等前端对话返工并重新交付后，再进入产品复验。
```

## 有条件通过示例

```text
BE-001 有条件通过。

验收判断：
- API 行为整体符合产品预期，但合并前必须补充错误响应测试。

未通过点 / 条件：
- 合并前需要补充错误响应场景测试。

需要返工的对话：
- 后端

需要更新的文档：
- [ ] docs/tasks.md
- [ ] docs/api-contract.md（如果响应结构变化）

可直接复制给后端对话的指令：

请继续处理 BE-001。

产品验收为有条件通过，合并前必须补充：
- 为错误响应场景增加测试。
- 确认响应结构仍符合 docs/api-contract.md。

完成后把验证结果交回产品对话复验。若响应结构变化，请同步更新 docs/api-contract.md。

可直接复制给主控对话的指令：

BE-001 产品验收为有条件通过，暂时不要合并。

请主控对话执行：
- 等后端补充错误响应测试后再进入合并前验证。
- 在条件满足前，不要合并 BE-001 对应 PR。
- 将 docs/tasks.md 中 BE-001 状态标记为 Conditional / Rework / In Progress，按项目任务状态约定选择。
```
