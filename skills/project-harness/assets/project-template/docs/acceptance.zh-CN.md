# 验收模板

产品/架构对话验收前端、后端、Bug、实验对话的交付结果时，使用这个文档。

## 验收规则

每次验收必须给出下面三种结论之一：

- `通过`
- `不通过`
- `有条件通过`

如果不是完全通过，产品/架构对话必须输出可执行的下一步。不要只说“没做好”“不符合预期”，必须说明谁接下来做什么。

## 验收模板

```md
## YYYY-MM-DD 任务验收

任务：
验收人：
结论：通过 / 不通过 / 有条件通过

验收依据：
- PR 或分支：
- 截图或演示：
- 测试/build 结果：
- 相关文档：

验收标准检查：
- [ ] 标准 1
- [ ] 标准 2

问题：
-

返工要求：
- 责任方：前端 / 后端 / 主控 / 产品 / Bugfix / 实验
- 任务 ID：FE-001 / BE-001 / BUG-001
- 具体说明：
  -

需要更新的文档：
- [ ] `docs/tasks.md`
- [ ] `docs/product.md`
- [ ] `docs/api-contract.md`
- [ ] `docs/architecture.md`
- [ ] `docs/decisions.md`

下一步交接：
前端：读取 prompts/frontend.zh-CN.md，继续处理 docs/tasks.md 中的 FE-001。
后端：读取 prompts/backend.zh-CN.md，继续处理 docs/tasks.md 中的 BE-001。
主控：在返工完成前不要合并相关 PR。
```

## 交接示例

```text
FE-001 验收不通过。

原因：
- 移动端布局不符合验收标准。
- 缺少空状态。

请前端对话返工：
- 继续在当前分支处理 FE-001。
- 阅读 docs/tasks.md 中的 Rework Notes。
- 修复移动端布局和空状态。
- 运行 lint/build 后交回主控 review。
```

```text
BE-001 有条件通过。

条件：
- 合并前需要补充错误响应场景测试。

请后端对话继续：
- 继续在当前分支处理 BE-001。
- 为文档里的错误响应补测试。
- 如果响应结构变化，更新 docs/api-contract.md。
```
